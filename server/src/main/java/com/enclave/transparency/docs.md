# `transparency` — key transparency log

**Architecture position:** a small module that listens to `identity` device events and serves
proofs. It holds public keys and hashes only (specs §19.4, TRUST-01, ADR-0007).

| Type | Role |
|---|---|
| `TransparencyLog` | Appends one leaf per change of an account's identity key or device list (serialized by an advisory lock, dense indexes), signs a tree head on every append, serves heads/leaves, verifies and stores witness co-signatures. Leaf hashes are cached in memory for read paths (append-only, committed leaves only). |
| `KeyChangeListener` | Synchronous `@EventListener` on `DeviceRegistered`/`DeviceRevoked`: the leaf commits in the same transaction as the roster change. Backfills every account with an identity key at startup (no-op when up to date). |
| `MerkleTree` | RFC 9162 tree hash, inclusion paths and consistency proofs. |
| `KtEncoding` | Canonical `CONVO-KT-*-V1` bytes (device-list hash, leaf, head, co-signature). Shared vectors: `contracts/vectors/kt-v1.json` (generated by `contracts/scripts/kt-vectors.py`). |
| `KtController` | `GET /v1/kt/accounts/{id}?since=` (device-signed): newest head, newest witnessed head with co-signatures, consistency proofs from the witnessed head and from `since`, the account's newest leaf and its inclusion path. Public, hashes only: `GET /v1/kt/head`, `GET /v1/kt/consistency?from=&to=`, `POST /v1/kt/cosignatures` (accepted only with a valid signature by a configured witness). |
| `KeyTransparencyProperties` | `enclave.kt.signing-key` (base64 PKCS#8 Ed25519; generated and stored in `kt_signing_key` when empty — development only), `enclave.kt.witnesses` (`id:base64-raw-public-key`, comma-separated), `enclave.kt.max-witness-age` (default 7 days, a hint to clients, capped at 30 days client-side). |

Tables (V37): `kt_leaves`, `kt_heads`, `kt_cosignatures`, `kt_signing_key`.

Device-list hash = SHA-256 over the active devices' `(deviceId, registrationId)` sorted by ID — the
same roster `GET /v1/accounts/{id}/devices` returns, so clients recompute it from what they encrypt to.

Clients: `apps/web/src/core/keyTransparency.ts` (verification) and `core/ktMonitor.ts` (state,
results). Witness: `deploy/kt-witness`.
